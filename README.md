# 현대 하이브리드 중고 매물 주간 스크리너

엔카와 KB차차차에서 현대 하이브리드 중고 매물을 주간 단위로 걸러내는 스크립트.
대상은 코나 하이브리드, 아이오닉 하이브리드, 아반떼 하이브리드(CN7),
쏘나타 하이브리드(DN8)이며 각 페이스리프트를 포함한다.

아이오닉·코나의 **일렉트릭 트림은 제외**한다. 순수 EV는 충전 인프라가 걸린 다른
구매 결정이고, 배터리 보증 계산의 전제도 하이브리드와 다르기 때문이다.
대상 모델은 `screener/config.py`의 `ENCAR_MODELS`/`CCC_MODELS`에서 바꾼다.

## 실행

의존성 없음. Python 3.9+ 표준 라이브러리만 사용한다.

```bash
python run.py                       # 엔카 + 차차차 (기본)
python run.py --source encar        # 엔카만 (완전 검증만 필요할 때)
python run.py --out report.md       # 알림 메시지 저장
python run.py --json raw.json       # 통과 매물 원자료 저장
```

기본값이 `both`인 이유는 차차차 전용 매물을 놓치지 않기 위해서다. 다만 차차차는
단독 판정이 불가능하므로(아래 참고) 본 후보에 섞지 않고 "검증 불가" 목록으로
분리해 보여준다.

조건과 임계값은 전부 `screener/config.py`에 모여 있다.

## 필터 규칙

매물이 최종 후보가 되려면 아래를 전부 통과해야 한다.

| 규칙 | 기준 | 근거 |
|---|---|---|
| 가격 | 1,800만원 이하 | 차량가 기준. 이전비(취득세 등 100~150만원)는 별도 |
| 주행거리 | 100,000km 이하 | |
| 사고이력 | 성능점검 `accdient == false` | 골격 손상 여부. 외판 교환/판금 개수와 무관 |
| 실질 경과일 | `max(성능점검 등록일, 광고 최초등록일)` ≤ 2개월 | 아래 참고 |
| 렌트 이력 | 용도이력에 대여용 없음 | |
| 보험 피해금액 | 내차피해 + 타차가해 ≤ 500만원 | `accdient=false`여도 피해가 크면 제외 |
| 보험이력 공백 | 누적 3개월 이하 | 아래 참고 |
| 이력시작 지연 | 연식 대비 3개월 이내 | 아래 참고 |

### 실질 경과일을 max로 잡는 이유

딜러가 매물을 재등록하면 성능점검 등록일과 광고 최초등록일이 **따로따로**
리셋된다. 실제로 성능점검일만 당일로 리셋되고 광고는 58일째인 매물과, 반대로
광고만 15일로 리셋되고 점검일은 75일 전인 매물이 둘 다 관측됐다. 둘 중 세탁되지
않은 쪽(더 오래된 값)을 써야 실제 체류 기간을 잡을 수 있다.

`re_registered` 플래그는 판정에 쓰지 않고 출력에만 표시한다.

### 보험이력 공백

카히스토리의 "보험 미가입기간"은 **무보험 운행이 아니다.** 개인용 자동차보험
가입 이력이 조회되지 않는 구간을 뜻하며, 렌트·법인 차량은 공제조합이나 단체보험에
가입돼 이 구간이 길게 잡힌다. 문제는 **그 기간의 사고가 카히스토리에 남지 않아
무사고를 검증할 수 없다**는 점이다. 피해금액 0원이 무사고 증명이 아니라 이력
부재일 수 있으므로 공백이 긴 매물은 제외한다.

이 규칙 하나가 렌트 이력 매물을 사실상 전부 걸러낸다(관측된 공백 36~63개월).

### 이력시작 지연

공백 표기 없이 레코드 자체가 최근부터 시작하는 세탁 케이스가 있다. 2021년식인데
카히스토리가 당해 8월부터만 존재하고 같은 날 번호판이 새로 발급된 매물이 그 예다.
연식과 이력 시작일의 간격으로 잡는다.

### 렌트 이력 분류

카히스토리 용도이력은 단기렌터카와 개인 장기렌트를 **구분하지 않는다.** 현재 용도,
연평균 주행거리, 명의변경 횟수로 추정만 가능하다(`rules.classify_rent`).

- 단기렌터카 추정: 현재도 대여용이거나 연평균 20,000km 이상
- 장기렌트 추정: 대여용→자가용 전환 + 명의변경 1회 이상 + 연평균 19,000km 미만

기본값은 둘 다 제외(`INCLUDE_LONG_TERM_RENT = False`)다. 장기렌트를 포함하도록
바꿔도 보험공백 규칙에서 대부분 탈락한다.

### 배터리 보증 잔여

판정에는 쓰지 않고 정렬·참고용으로 계산한다. 현대 하이브리드 전용부품
(고전압배터리, 구동모터, HPCU)은 **10년 / 20만km** 중 먼저 닿는 시점까지
보증하며, 그 둘 중 먼저 오는 쪽을 잔여로 본다.

최초 개인 구매자에게 주어지는 "배터리 평생보증"은 소유권이 이전되면 소멸하고
신차 출고일 기준 10년/20만km로 돌아간다. 중고차를 사는 입장에서는 평생보증이
걸려 있던 차라도 항상 10년/20만km가 기준이다.

검색 상한이 10만km이므로 주행거리보다 기간이 먼저 닿는 매물이 대부분이다.
**실제 잔여 보증은 차대번호로 제조사 서비스센터 확인이 필요하다.**

## 플랫폼별 데이터

### 엔카 — 완전 검증 가능

| 항목 | 출처 |
|---|---|
| 매물 목록 | `api.encar.com/search/car/list/general` |
| 사고이력, 외판 수리, 점검 등록일 | `/v1/readside/inspection/vehicle/{id}` |
| 렌트, 피해금액, 보험공백, 차량번호 | `/v1/readside/record/vehicle/{id}/open` |
| 광고 최초등록일, 재등록 여부 | `/v1/readside/vehicle/{id}` |

- 검색은 `sr=|ModifiedDate|{offset}|{limit}`으로 페이지네이션한다. **limit을 20으로
  고정하면 모델당 20건에서 잘린다** — 과거 실행에서 35건을 놓친 원인이다.
  `PAGE_SIZE = 50`으로 두고 `Count`에 도달할 때까지 순회한다.
- 진단 API가 빈 응답(404)이면 중복 등록 Id이므로 조용히 건너뛴다.
- 상세페이지 HTML(`dc_cardetailview.do`)은 트래픽 제한으로 막히는 경우가 많다.
  같은 데이터를 주는 위 API를 쓴다.

### KB차차차 — 부분 검증만 가능

| 항목 | 가능 여부 |
|---|---|
| 매물 목록, 가격, 주행거리 | 가능 (`/public/search/list.empty`) |
| 렌트 이력 | **가능** — "용도이력 있음/없음"으로 직접 표기. 엔카보다 낫다 |
| 차량번호, 소유자변경, 보험이력 건수 | 가능 |
| 보험 피해금액 | **불가** — 건수만 공개, 금액은 로그인 필요 |
| 골격 사고 여부 | **불가** — 성능점검 원본이 autocafe/carmodoo/m-park 외부 호스트 |
| 보험이력 공백 | **불가** |

주의: 상세페이지의 "KB진단 무사고" 문구는 **사고 유무가 아니라 KB진단 프로그램
참여 여부**다. 미참여 매물에도 같은 안내 문구가 정적으로 들어 있으니 무사고
판정에 쓰면 안 된다.

따라서 차차차는 단독 판정이 불가능하고, 엔카와 교차 대조(차량번호 우선, 없으면
주행거리 근사)해 쓴다. 매칭되지 않는 차차차 전용 매물은 "검증 불가"로 분리 표시한다.

관측된 중복률은 약 77%였다. 딜러가 양쪽에 동시 등록하기 때문이다.

## 네트워크

두 사이트 모두 봇 감지가 있다. `screener/http.py`가 요청 간격(기본 0.35초)과
재시도를 관리한다. 차차차 상세페이지는 빠르게 연속 요청하면 3KB짜리 "로봇여부 확인"
페이지를 돌려주므로 응답 크기로 감지해 더 긴 간격으로 재시도한다.

## 주간 실행 상태

`.screener_state.json`에 지난 실행의 통과 매물 id를 저장해, 다음 실행에서 신규
매물에 🆕 표시를 단다. **이 파일은 저장소에 커밋해야 한다.** 예약 실행은 매번
새 컨테이너에서 돌기 때문에, 커밋하지 않으면 상태가 남지 않아 신규 표시가
영원히 동작하지 않는다.

```bash
python run.py
git add .screener_state.json && git commit -m "주간 스크리닝 상태 갱신" && git push
```
