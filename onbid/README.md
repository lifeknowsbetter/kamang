# 온비드 스카우팅 (onbid/)

온비드(www.onbid.co.kr) 공매에서 평일 저녁마다 네 갈래를 골라 권리분석·사진판단 리포트 초안을 만들고,
지난 후보의 낙찰 결과와 같은 종류 물건의 최근 낙찰 사례를 붙인다. 부동산 물건에는 소재지가 가까운 개발 사업
(`data/devzones.json`)을 사실로만 덧붙인다. 법원경매(courtauction.go.kr)와 등기부 실시간조회(iros.go.kr)는 쓰지 않는다.

| 트랙 | 대상 | 조건 |
|---|---|---|
| A 지분 부동산 | 부동산 · 매각 · 지분물건 · 압류재산 | 최저입찰가 1,000만원 이하, **전국**(산본에서 가까운 순) |
| D 단독 소액 부동산 | 지분이 아닌 토지 · 건물 호실 · 압류재산 | 같음. 임차인·전입세대·인수권리 등 위험 신호 표시, 농지는 제외 |
| B 동산 재판매 | 동산 · 매각 | 1,000만원 이하, 귀금속/시계/카메라/컴퓨터/명품 가방 + 감정가 대비 70% 이하 장비류. 유가증권·무형자산·회원권·기타권리및증권·폐기물 등은 분류로 제외하고, 이름에 출자증권·출자지분·공제조합·비상장·주권·회원권 등이 있으면 분류와 무관하게 제외(`config.MVAST_RIGHTS`) |
| C 자동차 | 자동차 · 매각 | 1,000만원 이하, `carfilter.py`가 구조적으로 실효 없는 물건을 뺀 나머지만 |

리포트에는 트랙별 목록 외에 **"🏗 개발 사업 연관 물건"** 절(전국 압류 부동산 목록 전체 기준)과 A·D 물건마다
**"🏗 개발 연관"** 줄이 들어간다.

사용자 조건: 성인 1인(군포시 산본동 거주), 자차 없음, 온비드 전자입찰로 집에서 처리, 소송 없이 협상·재매각만.
지역은 전국이되 `geo.py`가 산본동 기준 직선거리(시군구 대표 좌표, 대략치)로 가까운 물건을 먼저 보여준다.
1,000만원 이하 공매는 본전이 기본값이라(아래 "판정 규칙") 리포트는 수익 목록이 아니라 실효 없는 물건을 거르는 필터다.

## 실행

Node(Playwright + Chromium)와 Python 3(Pillow), poppler-utils(pdftotext·pdfimages·pdftoppm)가 필요하다.
클라우드 세션 이미지에는 모두 들어 있다.

```bash
python3 -m onbid.run --out out/onbid              # 검색→상세→사진·감정평가서→초안 (20~30분)
python3 -m onbid.run --out out/onbid --skip-search  # 검색 결과 재사용, 끝난 상세는 건너뜀
python3 -m onbid.run --out out/test --skip-search --no-state   # 시험 실행(추적 상태 파일을 저장하지 않음)
```

산출물
- `out/onbid/report_draft.md` — 숫자·원문이 다 채워진 초안. `⟪…⟫`만 사진을 보고 채우면 된다. 개발 연관 절 포함.
- `out/onbid/candidates.json` — 후보별 전체 데이터(등급 근거, 회차표, 등기 행, 명세서 원문, 지원금 추정, 출구 계산, 감정평가서 신호,
  `dev`)와 전국 목록의 개발 연관 집계 `devscan`.
- `out/onbid/media/<물건관리번호>/` — `photos_sheet.jpg`(온비드 사진 모음), `appraisal_sheet*.jpg`
  (감정평가서 중 사진·도면이 든 쪽 모음), `apsl-pNN.png`(쪽별 100dpi), `appraisal.txt`(글자 층이 있을 때).
- `onbid/state/tracked.json` — 추적 상태(저장소에 커밋). `--no-state`면 저장하지 않는다.

시험(네트워크 없이 돈다. Node와 Python만 필요)

```bash
python3 -m unittest discover -s onbid/tests -t .          # 코드 시험 (2026-10-18 기준 450개, 30초 안팎)
ONBID_FIXTURES=<수집본 폴더> python3 -m unittest discover -s onbid/tests -t .   # 실제 수집본(search_*.json, items/, media/)이 있을 때 추가로 도는 시험
python3 -m onbid.devzone validate                          # 개발 사업 데이터 검사 (오류 0이어야 커밋)
```

수집본이 없으면 그것을 쓰는 시험은 건너뛴다(저장소에는 감정평가서·상세 원문을 넣지 않는다).
코드를 고친 뒤에는 위 시험을 돌려 통과시킨 다음 커밋한다.

```bash
python3 -m onbid.track mark out/onbid <물건관리번호>...  # 오늘 리포트에 실은 물건 표시
python3 -m onbid.track show                              # 추적 현황
```

## 단계

1. `js/search.js` — 조건검색 3종을 100건씩 페이지 넘겨 받는다(입찰기간 오늘~1개월, 사이트 기본값).
2. `analyze.select_*` — 1차 선별. A는 지분(`alcYn=='Y'`)·압류재산, D는 비지분 압류재산(같은 건물·가격 호실은 묶음),
   둘 다 산본에서 가까운 순으로 상세를 연다(A·D 각 30건). B는 권리형 제외 → 키워드·가산점·거리, 한 기관이 5건 넘게
   독차지하지 못하게 분산(40건). C는 `carfilter`로 실효 없는 물건을 뺀 뒤 가까운 순(15건).
3. `js/details.js` — 후보별 상세 화면, 등기·점유·임대차·배분요구 조각, 사진 목록, 공매재산명세서.
4. `parse.py` → `analyze.build_*` — 리스크 등급, 회차표, 플래그, 지원금 추정, 출구 계산(`exit_numbers`), 개발 연관 매칭(`devzone.match`), 정렬.
5. `media.py` — 상위 후보(A 8·D 8·B 14·C 5)의 사진과 감정평가서 PDF를 받아 모음 이미지를 만든다. 링크도 이때 확인한다.
   이어서 `analyze.apply_appraisal`이 A·D의 감정평가서 본문(`appraisal.txt`)에서 맹지·급경사·현황 농지·분묘 신호를 뽑아
   등급을 다시 매기고, 사진 판단 뒤의 순서로 `sort_A`·`sort_D`를 다시 돌린다.
6. `track.py` + `js/results.js` — 추적 중인 물건 중 개찰이 지난 것의 결과(낙찰가·낙찰가율·응찰자 수·유찰)를 받고,
   동산·자동차 후보마다 같은 키워드(차종·순금·18K·노트북·카메라 브랜드 등)의 최근 90일 낙찰 사례를 받는다.
   오늘 사진까지 본 후보를 추적 목록에 넣고, 45일 동안 다시 안 보이면 지운다.
7. `devzone.scan` — 상세를 열지 않은 전국 압류 부동산 목록 전체를 개발 사업 데이터와 맞춰 `devscan`을 만든다.
8. `report.py` — 초안 작성. 후보마다 `🆕`(처음) / `↻ MM/DD 보고`(전에 리포트에 실음) / `검토 MM/DD~` 표시.
9. (리포트를 쓰는 모델) media 폴더의 사진·감정평가서를 직접 열어 ⟪…⟫를 채우고, 사진상 문제 있는 후보는 다음 후보로
   바꾼다. 루틴 지시문은 `ROUTINE_PROMPT.md`에 있다.

## 온비드 동작에서 확인한 사실 (코드가 기대는 부분)

- **조건검색 폼은 화면의 첫 자동검색이 끝나야 채워진다.** 빈 폼으로 검색하면 서버가 "지금 입찰중"인
  물건만 돌려줘 다음 주 입찰 예정 물건이 빠진다(288건 → 35건). `search.js`가 기다렸다가, 그래도 비면 기본값을 직접 넣는다.
- **지분여부 필터(srchAlcYnType)는 서버에서 무시된다.** 응답의 `alcYn=='Y'`로 직접 거른다.
- **상세 화면은 POST 이동으로만 열린다.** 직접 GET은 400. 단, 공유용 형식
  `mvmnCltrDtl.do?cltrScrnGrpCd=&cltrPrptDivCd=&onbidCltrno=&onbidPbancNo=&pbctNo=&pbctCdtnNo=`
  (이 6개만)은 GET으로 열려서 리포트 링크로 쓴다.
- **등기사항증명서 주요정보·점유관계·임대차·배분요구는 XHR 조각으로 늦게 채워지고 3~10건씩 페이지가 나뉜다.**
  `pageUnit=100`으로 직접 다시 받아야 공유자가 빠지지 않는다.
- **공매재산명세서는 ClipReport 뷰어 팝업이다.** 입찰 시작 7일 전부터만 버튼이 생긴다. 리포트 서버 응답의
  `viewData`(base64 JSON, 글자 단위 URL 인코딩)를 풀어 텍스트로 만든다. 인수권리·지상권·기타 유의사항은 보통 2쪽이라
  "다음" 버튼을 눌러 받아야 한다.
- **감정평가서 PDF는 로그인 없이 받아진다**(`dnldFile.do?atchFileLstNo&atchSn&hashCrpsNo`, 값은 상세 화면의
  `fn_chkPdfRead(...)`). 토지 감정평가서에는 위치도·지적도·위성사진·현장사진이 있고, 자동차 감정평가서(오토마트 등)는
  스캔본으로 감정평가표(상태 체크)·사고이력 보고서·차량가액 범위가 들어 있다. 한 감정평가서가 여러 물건(기호1·기호2)을
  함께 다루기도 하니 주소·기호로 해당 물건을 골라 본다. 파산재단 물건의 공고문 PDF는 별첨이 스캔본 이미지(7~8쪽)인 경우가 있다.
- **사진은 `inqCltrMapImg.do` 팝업 조각에 URL 목록이 있고 GET으로 받아진다.**
- 지자체(예: 전북특별자치도) 공고 동산은 명세서·감정평가서가 hwpx 첨부라 자동 열람하지 않는다. 사진으로 판단한다.
- **입찰결과는 로그인 없이 공개된다**(물건입찰결과 화면 `mvmnCltrBidRsltClg.do`, XHR `cltrBidRsltClg.do`).
  폼이 늦게 채워져서 화면의 첫 자동조회 요청 본문을 가로채 기본값으로 쓴다. `srchCltrMnmtNo`+`searchCltrMnmtNoYn=Y`면
  날짜 조건과 상관없이 그 물건의 회차별 결과가 다 나온다. 키워드는 `srchCltrNm`+개찰일 범위(`srchOpbdBgdd`~`srchOpbdEndd`).
  낙찰가 `onbidBidAmt`, 최저가 대비 낙찰가율 `rateRow1`(%), 응찰자 수 `totalBid`, 결과 `pbctStatNm`(낙찰/유찰/취소 등).
  키워드 검색에는 의료·산업용 장비가 섞여서(예: '카메라'→안저카메라) 이름으로 걸러 낸다.
- 입찰결과 화면의 기본 개찰기간은 1개월이라 장기 통계는 개찰일 범위를 직접 넣어야 한다(`results.js`는 키워드 조회에서 `from`~오늘을
  넣는다). 출자증권 같은 권리·증권류는 `srchCltrType`을 비우면 0건이었고 동산 유형(`0003`)으로 조회해야 잡혔다(2026-10-18 확인).
- 2026-10 확인한 동종 낙찰: 저가 차량은 경쟁이 세서 최저가의 110~234%에 낙찰된다(모닝 83건 중앙값 165%,
  스파크 126%, 모하비 144%). 최저가 입찰은 거의 의미가 없다.
- 클라우드 세션의 프록시는 온비드 외 대부분 도메인을 막는다. 배출가스 등급 조회 같은 외부 사이트는 자동 조회하지 않는다.

## 판정 규칙

### Track A 리스크 (사용자 지침) — `analyze.grade_A`, `apply_appraisal`
- 낮음: 농지 아님 + 공유자 없음(또는 전원 10년 이상 지나 비활성 추정) + 인수권리·점유자 없음
- 중간: 농지 아니지만 공유자 있음. 등기 주요정보가 0건이라 공유자를 확인할 수 없는 경우도 중간
- 높음: 농지이거나 실제 인수권리(명세서) 또는 점유·임대차 존재
- **감정평가서 본문 신호**(`appraisal_signals`, 사진을 보기 전에 코드가 먼저 뽑아 모델이 지형을 잘못 쓰는 일을 막는다):
  맹지(R), 지목은 대지 등이나 현황은 전·답(경작 중)(R, 농지법은 지목과 무관하게 실제 경작지를 농지로 본다), 급경사·차량 접근 불가·
  분묘·제시외 건물(Y), "분묘 소재 가능성" 같은 일반 유의 문구(I, 등급 영향 없음). R이 있으면 높음, Y가 있으면 낮음을 중간으로 올린다.
  인근 사례 지가표 줄(숫자로 끝나는 줄)과 "맹지가 아님"은 걸러 낸다. 뽑힌 원문 줄은 초안에 그대로 나온다.
- **`bad_exit`**: 맹지·분묘(실제 언급)가 감정평가서나 유의사항에 나오면 되팔 상대가 거의 없어 초안에 ⛔를 붙이고 입찰을 권하지 않는다.
- **출구 계산**(`exit_numbers`, 코드가 계산해 초안 🧮 줄로 낸다. 모델이 손으로 다시 계산하지 않는다)
  - 예산 상한 = (1,000만 − 등기 실비 5만) ÷ 1.046
  - 출구 상한 = (감정가×0.7 − 실비 5만 − 교통비 3만 − 목표이익 30만) ÷ 1.046. 감정가는 이미 지분 감정가라 지분비율을 다시 곱하지 않고,
    시세 대신 감정가를 넣은 '위쪽 한계'다(감정평가서에 낮은 지가 자료가 있으면 더 낮아진다).
  - 못 팔면 손실 = 현재가×1.046 + 5만 − 감정가×0.2(지분 매입업체에 감정가의 20%로 넘길 때. 20%는 (미확인) 가정)
  - 출구 상한·예산 상한 이하가 되는 첫 회차는 온비드에 등록된 회차표에서 찾는다.
- 정렬: 위험 높음은 뒤로 → 산본에서 가까운 구간 → 리스크 → 개발 연관(동순위 보조) → 감정평가서 이용상태가 '자연림·임야 상태'가 아닌 땅 먼저
  → 지목(임야·대지·도로·구거 > 기타 토지 > 농지) → 가격. 2026-10 사진 판독에서 상위 낮음 등급 대부분이 이용 흔적 없는 맹지 자연림이었고,
  되팔 상대가 보이는 땅(옹벽·진입로·경작지·관리 분묘)은 이용상태 문구로 1차 구분이 됐다.
- 다음 회차 가격은 추정하지 않고 온비드에 이미 등록된 회차표를 쓴다. 한국자산관리공사 압류재산은 매 회차
  최초 예정가의 10%씩 일정하게 내려간다(전회차의 88~90%라는 통념보다 빠르다).

### 개발 연관 (`devzone.py`, 데이터 `data/devzones.json`)

물건 소재지(온비드 행의 `sidoSgkEmd` 문자열)를 국토부·지자체 개발 사업, 대기업 신설 부지(반도체 등), 산업단지, 교통, 신공항 항목과 맞춰
"이 물건이 어떤 사업과 가까운가"를 리포트에 사실로만 보여 준다. **위치가 가깝다는 사실일 뿐 수익이 아니다.** 순위에는 위험 등급 다음의
동순위 보조로만 쓰고(`best_tier`), 위험 등급은 바꾸지 않는다.

- **항목 필드**(`validate`가 검사): 필수 `id`(중복 불가)·`name`·`kind`·`stage`·`sido`·`sgg`·`summary`·`asof`(YYYY-MM 또는 YYYY-MM-DD, 미래 불가)·
  `sources`(http URL 1개 이상)·`confidence`(high/medium/low). 선택 `emd`·`neighbors_sgg`(인접 시군구)·`lat`+`lng`(함께, 한국 범위)·
  `investor`·`scale`·`schedule`·`land_rules`(토지 거래 규제). `kind`는 반도체·첨단산업, 대기업 투자·신설 부지, 산업단지,
  신도시·공공주택지구, 도시개발·재정비, 교통, 신공항·항만, 기타. `stage`는 계획 → 구역지정 → 승인·착공 → 조성·건설중 → 준공·가동, 그리고 보류·취소.
  기준일이 400일을 넘으면 경고한다. 자세한 스키마는 `data/README.md`.
- **매칭 3단계**: ① 읍면동 일치(같은 시·구 안에서 `emd`에 물건의 읍면동이 있음) ② 같은 시·구인데 항목에 `emd`가 없어 사업 위치가 읍면동까지
  특정되지 않음 ③ 같은 시·구 안 다른 읍면동(항목에 `emd`가 있는데 물건은 다른 곳), 인접 시군구(`neighbors_sgg`, 같은 시 다른 구, 좌표가
  있으면 시군구 중심에서 12km 이내), 읍면동 없이 여러 시군구에 걸친 노선·광역 사업 통과. '보류·취소' 항목은 보여 주되 순위 보조에서 뺀다.
- **한계**: 온비드 행에는 좌표가 없고 읍면동까지만 있다. 시군구 중심 좌표는 ±5km 대략치라 구역 경계를 알 수 없다. 읍면동 일치도
  구역 안이라는 뜻이 아니므로 고시 도면(토지이음)에서 지번을 확인해야 한다.
- **법적 사실(2026-10-18 조사, 근거 수준은 `knowledge/KNOWLEDGE.md` 2-14)**: 압류재산(국세·지방세 체납처분) 공매는 부동산 거래신고법 시행령
  제11조제3항제12호로 토지거래허가가 적용되지 않는 것으로 읽는다(법령 사본 대조, 법제처 원문과 시행일 확인 남음). 다만 되팔 때 매수인은
  허가구역이면 허가가 필요할 수 있어 출구가 좁아진다. 구역 안 토지 보상은 해당 사업으로 오른 가격이 보상에 얹히지 않고(토지보상법 제67조 제2항), 이주대책·협의양도인택지·대토보상·양도세 감면은
  지분만 가진 공매 취득자에게 기대하기 어려워 수익 계산에 넣지 않는다(검색 발췌 수준, 근거와 한계는 `knowledge/KNOWLEDGE.md` 2-14).
- **미검증 후보**: `data/devzones_pending.json`은 검증 전 후보를 두는 곳이다(2026-10-18에 있던 후보는 모두 확인해 옮기거나 뺐다). `devzone.py`는 이 파일을 읽지 않아 리포트에 쓰이지 않는다. 일요일 공부 루틴이 후보를 확인해 옮긴다.
- **리포트**: A·D 물건마다 최대 2건의 "🏗 개발 연관" 줄(사업명·단계·기준일·신뢰도·출처 링크, 일정·토지 규제가 있으면 함께)과 주의 문구,
  그리고 "개발 사업 연관 물건" 표(1·2단계를 우선, 8건보다 적으면 3단계로 채움). 후자는 상세 검토 전의 1차 목록이다.
- **명령**: `python3 -m onbid.devzone validate`(오류 있으면 종료코드 1), `match "경기도 용인시 처인구 원삼면"`(한 소재지의 연관 항목),
  `scan <search_A.json>`(검색 결과 전체의 연관 건수).
- **갱신**: 공부 루틴이 일요일마다 기준일이 오래된 항목 6~8개를 다시 확인하고 새 대형 사업을 최대 3개 추가한다. 출처 URL·기준일 필수,
  확인 못 한 항목의 기준일은 바꾸지 않는다. 취소된 사업은 삭제하지 않고 `stage`를 '보류·취소'로 바꾼다. `validate`가 오류 0이어야 저장한다.

### Track C 조기폐차 지원금 (`subsidy.py`, 2026년 기준)

신청 전에는 반드시 해당 지자체 공고로 다시 확인한다.

- 대상: 배출가스 **4등급 경유차**, **5등급 차량**(5등급은 휘발유·LPG 포함). **5등급 지원은 2026년이 마지막**

- 요건(모두 충족): 신청일 역산 **6개월 이상 소유**(2026년부터 전 차종, 상속만 합산) · 사용본거지 기준 대기관리권역
  또는 신청지역 **6개월 이상 연속 등록** · 관능검사 적합 · 대상차량확인서 **정상가동** 판정(정기검사로 대체 불가,
  사고·침수로 가동불가면 탈락) · 정부지원 DPF·저공해엔진 개조 이력 없음 · 자진폐차말소만 인정 · 관용차 제외.

  - 4등급 경유: 1차 70%, 2차 30%는 전기·수소·하이브리드(경유 하이브리드 제외) 구매 시에만, 1·2차 합산 상한 800만원.
  - 5등급: 100%, 상한 300만원, 2차 없음.
  - 저소득층·소상공인 100만원 추가(상한 안에서). 3.5톤 이상은 배기량 구간별 상한표 별도.
- 운영: 지자체별 선착순·예산소진, 1인 1대가 많다. 2026년 접수는 대부분 마감(서울 10/16, 인천 본접수 8/31).
- 등급 추정(경유): ≤2005년식 5등급 · 2006~2007년식 4·5등급 혼재 · 2008~2009년식 4등급 · 2010~2011년식 대부분 3등급이나
  일부 모델 4등급(2010 쏘렌토R 일부, 2008~2011 포터2 126마력 등) · 2012년식 이후 3등급 이하(대상 아님).
  등급은 연식이 아니라 인증 배출허용기준으로 정해지므로 차량번호로 emissiongrade.mecar.or.kr(1833-7435)에서 확정한다.
- **공매 낙찰차 적용**: 낙찰·이전등록 후 6개월을 채워야 신청 가능 → 5등급은 사실상 불가, 4등급은 2027년 사업이

  취득세 과세표준이 낙찰가가 아닌 시가표준액일 수 있는 점, 정상가동 탈락 위험을 빼고 계산한다.
