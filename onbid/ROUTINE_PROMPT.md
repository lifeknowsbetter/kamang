## 2. 실행

    cd ~/kamang && python3 -m onbid.run --out out/onbid

20~30분 걸립니다. 끝나면 out/onbid/report_draft.md(초안), candidates.json(전체 데이터), media/(사진·감정평가서 모음)가 생깁니다.
이 실행은 onbid/state/tracked.json(지난 후보 추적 목록)을 읽어 개찰이 지난 물건의 낙찰 결과를 조회하고, 동산·자동차 후보와 같은 종류의 최근 90일 낙찰 사례를 붙입니다.
실패하면 로그로 원인을 한 번 진단하고 `--skip-search`로 이어서 재실행합니다(끝난 상세는 건너뜀). 그래도 실패하면 수집 실패로 보고합니다.

## 3. 사진·감정평가서 판단 — 반드시 이미지를 직접 열어 볼 것
초안의 ⟪…⟫ 자리는 후보마다 적힌 media 파일을 Read로 직접 열어 보고 채웁니다. 이미지를 보지 않고 추측하지 마세요.
- Track A(토지 지분): appraisal_sheet*.jpg(위치도·지적도·위성사진·현장사진)와 photos_sheet.jpg. 그냥 산(자연림·방치)인지, 관리된 땅(경작·정리된 대지·포장도로·옹벽·건물·주차 등 실제 이용)인지 판단하고, 진입로/맹지, 경사, 분묘, 무단 점유, 경계 표식을 봅니다. 한 감정평가서가 여러 물건(기호1·기호2)을 다루면 이 물건 주소·기호의 사진만 봅니다. 글씨가 안 보이면 apsl-pNN.png(쪽별 100dpi)를 엽니다.
- Track B(동산): photos_sheet.jpg(+감정평가서가 있으면). 실물 상태, 작동 단서(시계 바늘·용두·유리, 화면 점등, 부속·배터리·충전기), 금 각인(24K/18K/14K/999/750/585)·브랜드·모델·중량 표기를 읽고 모조품·파손·부속 누락을 확인합니다.
- Track C(자동차): photos_sheet.jpg와 감정평가서(스캔본이면 apsl-pNN.png를 직접 읽기). 감정평가표의 상태 체크(배터리·엔진·변속기, 시동), 사고이력 보고서(내차피해 금액·횟수), 주행거리 이력, 차량가액 범위, 외관 손상·부식, 계기판 점등·경고등, 엔진룸 누유를 봅니다.
사진에서 문제가 드러난 후보는 순위를 내리거나 빼고, 초안의 다음 후보로 채웁니다. 사진만으로 확실하지 않은 것은 "사진상 ~로 보임", "사진으로 확인 불가"로 씁니다.

매일 돌기 때문에 같은 물건이 반복됩니다. 초안 제목 옆 표시를 씁니다: `🆕` 처음 본 물건, `↻ MM/DD 보고` 전에 리포트에 실은 물건, `검토 MM/DD~` 후보로만 봤던 물건.
- 신규(🆕·검토)를 먼저 자세히 쓰고, ↻ 물건은 가격·회차·마감·판단이 바뀌지 않았으면 트랙 끝 "계속 진행 중" 목록에 한 줄(물건명 링크 · 현재가 · 마감 D-n)로만 줄입니다. 사진 판단은 이전과 같으면 다시 하지 않아도 됩니다.
- 상위 개수(A 5 / B 10 / C 5)는 자세히 쓰는 물건 기준입니다. 신규가 모자라면 ↻ 물건으로 채워도 됩니다.

## 3-1. 입찰가 범위
동산·자동차 후보에 초안의 "📈 동종 낙찰"(최근 90일 같은 키워드 낙찰 건수, 낙찰가율 중앙값, 사례)이 있으면, KNOWLEDGE.md "6. 입찰가 산정 규칙"과 함께 써서 "권장 입찰가 범위"를 냅니다.
- 낙찰가율 중앙값 × 이번 최저가 = 예상 낙찰가. 되팔 가격(금은 무게×매입 단가, 전자제품·차량은 중고 시세 — 모르면 "시세 확인 필요")에서 비용(이전비·탁송·세금 등)과 목표 마진을 뺀 값이 상한입니다.
- 상한이 예상 낙찰가보다 낮으면 "경쟁 과열 — 패스 권장"이라고 씁니다. 근거 숫자를 함께 적고, 사례가 3건 미만이면 "사례 부족"을 밝힙니다.

## 5. 추적 표시와 저장 (리포트를 다 쓴 뒤)
오늘 리포트에 자세히 쓴 물건(A·B·C, "계속 진행 중" 한 줄 목록 제외)의 물건관리번호를 표시하고 상태 파일을 올립니다. 내일 이 물건들의 낙찰 결과를 찾아 보고하는 데 쓰입니다.

    cd ~/kamang && python3 -m onbid.track mark out/onbid <물건관리번호> <물건관리번호> ...
    git add onbid/state/tracked.json && git commit -m "온비드 추적 상태 $(date +%F)" && git pull --rebase origin claude/onbid-weekly-scouting-b8yrsl && git push origin claude/onbid-weekly-scouting-b8yrsl

push가 실패하면 한 번 다시 시도하고, 그래도 안 되면 리포트 끝 안내문 바로 위에 "추적 상태 저장 실패(내일 결과 추적이 빠질 수 있음)" 한 줄만 붙입니다. 리포트는 이 단계 뒤에 최종 응답으로 냅니다.
